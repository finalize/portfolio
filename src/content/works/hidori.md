日程調整の出欠表。イベント名と候補日を入れると URL ができるので、それを配ると全員が ○△× で答えられる。登録は要らない。

調整さんと同じ形だが、作った動機は Next.js の App Router を実地で覚えることだった。技術のほうが先にあって、それに見合う題材を探した結果がこれになった。小さいのに、Server Component と Client Component の境界・Server Actions・動的ルート・Cookie と、覚えたいものがひと通り出てくる。

## 調整さんと違うところ

**自分の回答は自分だけが直せる。** 調整さんは URL さえ知っていれば誰でも他人の行を書き換えられる。hidori は回答したときに編集用のトークンを発行して、その端末の Cookie に入れる。別の端末から直したい人には、そのとき一度だけ引き継ぎリンクを見せる。

**狭い画面では表をやめる。** 候補と参加者が増えると、あの表は横に伸びて読めなくなる。46rem より狭いときは候補ごとのカードに切り替えて、○ が何人・△ が何人という集計を主役にする。スマホで知りたいのは「どの日が有力か」であって、誰が何を答えたかは開いて見ればいい。回答するときも表のセルは押させず、候補を縦に並べて大きなボタンを置く。

**90日で消える。** 最後に誰かが触ってから数える。他人の名前とコメントを無期限に持ち続けたくないので、cron で実際に削除している。

## 作りの要点

| | |
|---|---|
| 集計表 | Server Component。D1 から読んで描くだけで、JS を送らない |
| ○△× を選ぶところ | Client Component |
| 書き込み | Server Actions。入力は zod で検証してから DB に触る |
| 候補日の入力 | shadcn の Calendar。表示用の文字列はサーバ側で組み立てる |
| 掃除 | Cron Trigger。OpenNext が作る fetch ハンドラを包んで `scheduled` を足している |

配色は自作の [contrast-kit](/works/contrast-kit/) で検査していて、コントラストが足りないと CI が落ちる。

## 覚えたことより、間違えたことのほうが多かった

**`"use server"` のファイルは async 関数しか export できない。** 定数を1つ再 export しただけでビルドが落ちた。

**CSP を絞りきれなかった。** `script-src 'self'` にしたら、インラインスクリプトが7件ブロックされて React がハイドレーションに失敗した。App Router は RSC のペイロードをリクエストごとに違うインラインスクリプトで流すのでハッシュでも指定できず、nonce を配るには middleware（Next 16 では proxy）が要るが、そちらは nodejs ランタイム専用で OpenNext が対応していない。`script-src` だけ緩めて、理由を設定にコメントで残した。

**フォームを制御していなかったので、検証で弾かれると入力が全部消えていた。** React の form action は送信後に未制御の入力を初期化する。

**広い画面で表とカードが両方出ていた。** 幅で切り替えるメディアクエリを CSS の途中に書いたせいで、あとから出てくる同じ詳細度の指定に負けていた。

どれも動かして初めて分かった。ビルドが通ったことを動作の証拠にしない、というのを何度も確かめる羽目になった。
